# 桌面适配设计

状态：已确认并接入代码。niri 已完成自动测试与真实窗口回归；macOS + yabai、原生 macOS 尚未实机验收，标为实验性。GNOME、Windows 和其他 WM 不在本次实施范围。

## 职责拆分依据

调整前，平台实现分散在多个调用方：

- [desktop.py](../src/agent_done/desktop.py) 同时承担 Linux 进程身份、niri 查询和事件监听，还直接更新状态库及清理绑定。
- [navigation.py](../src/agent_done/navigation.py) 选择待查看目标，同时直接执行 niri 聚焦命令。
- [runtime.py](../src/agent_done/runtime.py) 直接订阅 niri，并依赖 Linux 进程启动标识清理绑定。
- [state.py](../src/agent_done/state.py) 的连接状态和位置计算带有 niri 语义；[cli.py](../src/agent_done/cli.py) 的诊断也直接查询 niri。

用户已确认这项模块与职责调整。下文记录实施所遵循的接口和行为契约；macOS 使用方法及实测入口见 [macOS 接入说明](macos.md)。

| `desktop.py` | 桌面后端选择与统一接口；调用方不再依赖具体 WM 命令 |
| 新增 `desktop_niri.py` | 承接现有 niri 查询、聚焦和事件解析，输出标准化桌面状态 |

| `navigation.py` | 保留待查看队列排序、有效目标选择；通过桌面接口请求聚焦 |
| `runtime.py` | 保留服务、订阅和生命周期编排；接收标准化桌面状态，再调用状态逻辑更新绑定及查看状态 |
| `state.py` | 保留会话、请求、去重和待查看状态；消费标准化位置与连接信息 |
| `codex.py`、`cli.py` | 保留启动/协议观察与命令职责，改用统一进程、桌面接口 |
| `waybar.py`、`install.py` | 保留 Linux 展示和安装职责；不把 Waybar 作为 macOS 跳转前提 |

不增加插件框架、独立协调进程或新的远程协议。现有 Codex 转发器、SQLite 和 Unix IPC 继续使用。

## 接口与行为契约

桌面接口提供四项能力：

1. 登记调用方所在的准确 OS 窗口，不能用事件发生时的前台窗口或目录标题猜来源。
2. 查询窗口列表、准确焦点、连接状态及可用的位置元数据，以检查目标是否仍有效。
3. 请求聚焦目标；结果只说明请求是否发出，不能据此确认已查看。
4. 观察桌面状态变化；允许后端使用原生事件或有界查询，只有观察到准确目标聚焦才触发查看确认。

后端负责系统交互和数据规范化；会话绑定、失效清理、请求生命周期及待查看确认仍由 agent-done 的服务和状态逻辑负责。

桌面适配实例由现有用户服务持有。启动器通过本地控制接口登记来源，跳转命令通过同一服务激活目标，避免跨进程复制 AX 对象。

目标身份包含后端名称和不透明窗口 ID。旧数据库记录按 niri 解释并迁移，保留现有会话数据；位置字段可以缺失，不能为非平铺窗口伪造行列。启动包装器、服务和跳转命令使用一致的后端身份，不能静默混用后端的窗口 ID。

队列仍按最近状态更新时间升序选择。跳转失败或焦点未确认时保留提醒；空队列不跳转；查看不代替授权或回答；每个 agent 继续使用独立 OS 窗口。

## 分步实施与范围

1. 提取接口并接回 niri。先保持现有 Linux 行为、命令和 Waybar 输出兼容，验证后再接入新后端。
2. 接入 Linux/macOS 进程身份和 yabai 后端。先验证来源绑定、两个独立窗口和实际焦点确认，再增加关闭、最小化、跨 Space 等验收项。
3. 接入原生 macOS 后端。优先公开系统或选定终端的接口；无法确认准确目标时保留提醒并报告原因，不以任意同应用窗口作为成功回退。

第一期 macOS 可使用命令入口和手动配置的快捷键。自动安装 launchd 服务、菜单栏、终端内部标签/分屏、私有 CGS 跨 Spaces 接口不在本次范围。原生全屏、跨 Spaces 等行为按实际测试结果分别记录，不能从当前 Space 的成功外推。

## 验证与交付

- 使用同一桌面接口验证后端契约：目标关闭、ID/进程复用、重名窗口、请求成功但焦点未变、连接中断与恢复。
- 现有状态、Codex 协议、导航和安装测试通过；新增测试应覆盖契约和失败路径，而不是仅断言实现内部调用。
- 在本机用两个真实 Kitty/niri 窗口回归来源识别、跳转和计数，测试事件使用隔离服务，不影响生产提醒。
- macOS 代码未进行真实桌面验证前标为实验性；提供可在对应机器执行的隔离验收入口，分别记录 yabai 和原生 macOS 的结果。
- 当前环境无法证明 macOS 已可用。自动测试、窗口机制验证、真实 Codex 集成和特殊桌面场景分别记录证据。
