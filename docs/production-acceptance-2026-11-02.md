## 修复与复核

服务最初重启时超过停止期限。隔离测试稳定复现：保留一个空闲订阅连接后发送 SIGTERM，3 秒仍未退出。原因是 Python 3.13+ 的 `Server.wait_closed()` 等待活动客户端，清理位于退出上下文之后。修复为先关闭监听和订阅客户端，再等待退出。回归测试包含真实 socket、断开的空闲订阅和连续 3 次进程退出；最终完整测试共 20 项，通过。

并发测试最初看到完成后计数清除。元数据诊断确认两次完成均成功创建提醒，随后实际焦点切回测试窗口而清除，行为符合定义。把测试窗口放在另一个工作区后，双待查看 2 → 1 → 0 验证通过；没有为测试改变“切回即已查看”的规则。临时诊断代码已移除。

恢复测试驱动最初携带新会话专用的权限覆盖参数，原生 Codex 拒绝“恢复远程任务时覆盖权限”。移除测试附加参数后，正式入口的普通恢复通过。恢复会话沿用原有权限设置。

## 验证边界

真实桌面验证了命令授权和内建 `request_user_input`。文件修改授权、权限包申请、旧版授权协议和 MCP elicitation 使用相同请求分类路径，但未逐一实测所有后端；不宣称所有插件的特殊交互都已覆盖。纯文字提问在回合完成时提醒。

隐藏会话不误清除、重复事件不重开、同一会话多窗口只计一次、服务重启持久化等由状态和协议测试覆盖。初版不支持 tmux/screen 多窗格、远程窗口和 IDE 嵌入终端。快捷键按用户要求继续暂缓，声音、邮件尚未实现。
