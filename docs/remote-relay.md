# 远程中转协议草案

iPhone 和已配对工作站通过同一中转服务通信。中转可部署在自管 VPS、家用服务器或其他支持 HTTPS 和长连接的主机。工作站和手机主动连中转，各自网络需要允许相应的出站连接。首版支持前台 App 和在线工作站。

## 信任与数据

- TLS 保护客户端到中转的连接。会话原文、标题、工作目录、审批说明、决定和回复在设备端加密，只在配对的另一台设备解密。
- 中转能看到客户端地址、设备路由标识、在线状态、消息大小与时序。这些信息足以验证路由资格和转发密文。
- 中转的设备凭据控制谁能使用服务。工作站独立维护允许读取历史和处理交互的手机公钥，只有本地确认过的设备能获得权限。迁移中转地址无需更换设备密钥，前提是设备身份和信任列表由端点持有。
- 中转被控制时可能丢弃、延迟或重放数据。协议要求端点验证对方身份及消息归属，并拒绝过期或已经处理的控制操作。设备私钥泄露和中转可用性属于不同的防护问题。

设备配对需要双向核对公钥。工程首轮可用受信渠道交换公钥文件，iPhone 界面可以随后通过二维码和本机确认简化这个动作。撤销手机时，工作站移除其授权，中转也撤销其连接凭据。

端到端方案候选为 RFC 9180 的 HPKE Auth 模式。Go 端和 Swift 端使用标准库实现或成熟密码库，并用跨语言测试向量验证互操作。HPKE 本身提供的重放保护有限，控制操作另校验交互状态、有效期和幂等键。具体套件、编码和序列规则在发布给 Swift 前冻结。[HPKE 标准](https://www.rfc-editor.org/rfc/rfc9180.html#section-9.7.3) · [Apple CryptoKit HPKE](https://developer.apple.com/documentation/cryptokit/hpke?changes=_2) · [Go CIRCL HPKE](https://pkg.go.dev/github.com/cloudflare/circl/hpke)

## 设备管理

首版是单管理员、自托管部署。建议先用服务器本机的管理命令登记设备、查看在线状态、轮换凭据和撤销设备。后续需要管理网页时，可以复用这些操作，由独立的管理员身份访问。

当前 Go 中转通过本机命令生成独立设备凭据，由管理员维护登记文件并触发重载。在线状态可通过传输协议查询。运行方法见 [外层传输规格](../protocol/relay-v1.md)。

- 每台设备有独立的路由 ID 和接入凭据。中转持久化设备 ID、角色、允许的路由关系、凭据校验值和启用状态。登记到中转只授予转发权限。工作站仍单独核对已配对的手机公钥。
- WSS 建连时用凭据认证，中转以登记结果确定发送方。每次转发都检查目标授权。撤销设备时关闭它的活跃连接并拒绝重连。[OWASP WebSocket 认证与授权](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html#authentication-and-authorization)
- 客户端首版只发送鉴权、路由和协议兼容所需字段。心跳用于判断连接在线。OS 类型、App 构建号、主机名和 Codex 健康状态暂不上报。

## 中转只处理外层信封

建议工作站和前台 iPhone 统一使用 WSS。外层使用版本化信封，包含目标路由标识、密文和处理连接所需的字段。中转根据已认证连接决定发送方身份，校验目标是否允许转发，限制消息大小、速率与等待时间。目标离线时立即返回路由状态。中转重启后，客户端重连并同步，审批没有跨离线队列。

端到端的内层消息包含会话列表、历史分页、订阅快照及审批或结构化提问的回复。中转可以确认转发状态。手机从工作站的加密响应得知操作是否被接受、目标是否已过期，以及 Codex 是否结束等待。

中转返回结构化的转发结果，运维侧可按离线、权限、限流和连接写入失败统计，日志排除凭据和消息体。App 在后台处理这些协议结果。自动刷新失败时维持已有界面并更新连接状态。用户主动发出的审批或回复未送达时，在原卡片保留操作上下文并提示可采取的下一步。送达结果未知时，先查询待处理状态，再决定是否提供重试。

工作站处理控制消息前核对发送设备、会话、交互 ID、所属 Codex 连接和有效期。同一个交互只能提交一次有效决定。响应沿原 Codex 连接回包，桌面和手机抢先提交时也遵守同一条规则。重新连接后先读取快照，随后继续接收增量消息。

## 实施顺序与验收

独立中转使用 [外层传输规格](../protocol/relay-v1.md)，端点联调用 [控制协议草案](../protocol/control-v1.md)。

1. 在当前仓库实现独立的 Go 中转程序。用两个模拟工作站和一个模拟手机验证认证、跨工作站隔离、目标离线反馈、断线重连以及密文字节完整性。
2. 在工作站端和 Go 测试客户端接入设备配对及端到端加密。用确定性测试证明篡改、冒充和重放无法触发审批，验证历史分页及本地与手机同时响应。
3. 接入 Linux 工作站的真实 Codex 代理，确认原生 TUI 和手机侧能收敛到同一结果。交付固定版本的协议、测试向量和消息样例，供 Swift App 独立开发。

## 配置工作站

分别在中转登记工作站和手机，允许双向路由。两端各用 `agent-done remote keygen -out device-key.json` 生成身份密钥，核对并交换公钥。工作站使用权限为 `0600` 的 `~/.config/agent-done/remote.json`，设置了 `XDG_CONFIG_HOME` 时使用对应目录。

```json
{
  "relay_url": "wss://relay.example.com/v1/connect",
  "device_id": "workstation-1",
  "token": "<工作站中转凭据>",
  "private_key": "<工作站 Base64 私钥>",
  "peers": {"phone-1": "<手机 Base64 公钥>"},
  "control_peers": ["phone-1"]
}
```

`peers` 中的设备可读取会话和文本历史。`control_peers` 为其中明确获得控制权限的设备，配置缺省时使用首版只读行为。升级早期联调配置时，请移除旧的 `workspaces` 字段。

更新工作站二进制和配置后，用 `systemctl --user restart agent-done.service` 加载。通过新版 `agent-done codex` 启动或恢复的会话才具备原连接控制能力。在多个桌面代理同时打开同一会话时，待处理回复走各自请求的原连接，继续对话需保留一个桌面连接。查看历史仍可使用现有只读通道。

工作站验证原请求和手机意图后交给 Codex。命令审批只提交一次性决定。命令缺少完整明细、涉及网络授权或工作站未取得文件变更明细时，界面只提供可用的拒绝操作。异步问题、密项和权限变更在桌面处理。手机发起新回合后，Codex 继续使用会话已有的沙箱和审批策略。

工作站将幂等记录保存在 Agent Done 状态数据库。记录包含请求摘要和处置状态。中途断线且无法确认结果时，客户端可查询该状态，工作站按同一幂等键保留原记录。协议字段和状态定义见 [控制协议 v1](../protocol/control-v1.md)。

### 手机新建会话

`control_peers` 中的设备可以在工作站用户主目录新建空会话。Agent Done 服务持有会话的 Codex app-server 连接，依照工作站的 Codex 配置发起回合。App 断线后仍保留原连接。服务停止后，当前控制连接结束，Codex 保留自己的会话历史。

自动审批由原会话连接执行。每个会话可单独开启和关闭，自动回应后续符合条件的命令审批。目录选择和从 App 恢复会话尚未开放。 [会话管理协议](../protocol/control-v1.md#会话管理扩展)

### SSH 会话

SSH 登录工作站后直接运行 `agent-done codex`。应用可以查看和控制仍经过代理的会话，沿用工作站配置的配对与控制权限。没有关联的 niri 窗口时，Waybar 仍会显示提醒，窗口定位、跳转和聚焦确认不可用。

客户端合盖休眠或掉网后，服务端可能需要一段时间才能检测到断线。普通 SSH 的伪终端挂断后，Agent Done 结束该 TUI 和它的代理连接，App 对该连接的实时控制随之关闭。共享的 Agent Done 服务和 Codex daemon 由各自的后台生命周期管理。重新登录后可用 `agent-done codex resume <会话 ID>` 恢复。需要在 SSH 断开后继续由 App 控制时，可以预先在工作站的 tmux 会话里启动 `agent-done codex`，由 tmux 保留 TUI 和代理。 [OpenSSH 服务端断线检测](https://man.openbsd.org/sshd_config#ClientAliveInterval)
